# 本 Fork 的维护方式

本分支保留自有插件和测试，在遵循 [项目约定](../AGENTS.md) 和 [通信协议](protocol.md) 的基础上跟进官方代码。

## 分支和远程

| 名称 | 用途 |
|---|---|
| `upstream` | 官方 `KKKKhazix/agent-autoloop`，只拉取，推送地址禁用 |
| `origin` | 用户 fork `zhjnerv/agent-autoloop`，本项目唯一推送目标 |
| `main` | 与已核实的官方 main 保持一致，不加入本 Fork 的修改 |
| `office` | 自有扩展维护分支，包含官方基线及独立的扩展提交 |

不向官方上游推送自有修改、创建 PR 或评论。发起任何写入前核对完整仓库名称，不依赖 GitHub CLI 对 fork 的默认仓库推断。

## 同步步骤

1. 在独立工作树中保存自己的变更并检查完整待发表范围。凭据、真实接收人、机器配置、数据库、日志和本地业务记录留在私有目录。
2. 拉取并固定官方 main 的完整提交；确认 fork main 没有独有提交后，按快进方式同步官方历史，保留上游作者。
3. `office` 已有历史时保留该历史，合入本轮固定的官方基线；首次建立时从该基线创建，并带入已保存的自有提交。
4. 解决冲突并检查组合后的行为。运行类型、格式、对应行为测试和必要的隔离安装检查。普通插件修改使用快速测试；涉及内核、协议或模拟时遵循 [验证范围](../AGENTS.md#验证范围)。
5. 隐私、身份和完整差异检查通过后，只把已验证的候选推送到 origin。部署另按实际安装版本和兼容性验收决定。

同步主目录保持 main。个人部署计划和历史报告可留在本地，但不要顺手加入公开提交。后续开发使用 office 的独立工作树；不要为了运行测试切换共享主目录。

## 当前扩展

- [Telegram 本人私聊通道](telegram-plugin.md)：卡片发送、原消息更新、本人按钮回答及文字回复。
- [agy 后台 Agent](agy-plugin.md)：Antigravity CLI 单次执行、指定会话续接和当前步骤用量。
- [插件源码](../plugins/telegram/channel.ts) 和 [专项测试](../tests/telegram.test.ts) 与官方内核保持分离，没有新增运行时依赖。

本机插件可安装在 `~/.agent-autoloop/plugins/telegram/channel.ts`；官方 app 位于另一个子目录。插件源码的更新、配置变更和官方程序升级分别验收。

本次扩展在 v1.6.3 基线上完成真实私聊按钮验收；跟进 main 后的本地测试记录写在提交交付说明中。源码通过测试不等于运行中的服务已经升级。
